2. Triage (T1–T5)

Verbatim from research/TRIAGE_CHECKLIST.md, parsed at build time.
T1
READ
the factsheet. List (internally) its 2–3 weakest facts — the ones that, if wrong, flip the verdict.
T2
IDENTITY SANITY:
do SPV/EIA/registry candidates cohere (same entity family, same county, compatible size)? Contradictions are findings — record them.
T3
CONTEST THE SCORE
with at most 10 targeted web checks aimed at the weakest facts: cancellation/suspension news, financing/PPA announcements, developer project page, county news. Use `search.py "<query>"` (never scrape search engines; the PUCT portal and SEC are blocked — puct.py/spv.py are the doors). An empty result is negative evidence: record it, move on.
T4
VERDICT:
`paper_dismissed` | `deep_candidate` | `ambiguous`, consistent with the gate unless you adjust the score. You may adjust ±15 points MAX and ONLY with a cited source (URL + one-line quote/paraphrase in `score_adjustment.citation`).
T5
WRITE
`triage_findings.json` (all prior schema fields PLUS `score_adjustment {delta, citation}`) and `triage.md` (≤40 lines: verdict, the factors you confirmed/contested, citations). Files on disk are all that survives.

3. Deep scan (D0–D5)

Verbatim from research/PLAYBOOK.md § Deep scan v2, parsed at build time.
D0
CHECKPOINT ZERO:
write findings.json skeleton (every schema key, null values) BEFORE any research. Read factsheet.json/md + triage_findings.json + inventory sources/ — IA PDFs are usually already there (verified_* naming; never cite unverified_* without eyeballing the parties page).
D1
IA SCHEDULE:
extract the milestone-schedule exhibit from each IA document on disk (In-Service / Trial Op / COD dates, financial security) → contractual_schedule (one row per document — amendments change amounts). If no IA on disk, run the systematic ladder (below) once — do not loop.
D2
SITE + IMAGERY:
fix coordinates (factsheet EIA coords are a candidate, not truth); cdse.py chips, ≤6 image reads total; save boundary-map pages → site.map_artifacts.
D3
GAP-FILL:
county records/news for what the factsheet couldn't answer — local tools first (spv.py, ch313/faa/tceq, search.py), web last.
D4
NARRATIVE:
independent COD + drift verdict + confidence; write dossier.md.
D5
DETERMINISTIC WRAP-UP
(in order): queue_history.py <INR> → eia_history.py <INR> --write → build_brief.py <dir> → build_index.py. Then a final findings.json pass.

5. Where v1 agents failed

Dead-domain retry storms

ADDRESSED
3,011 WebFetch calls to the PUCT Interchange portal, 3,010 of them (100.0%) HTTP 402 — plus SEC EDGAR failing 100.0% across 1,196 calls. Worst single-run loop: 26 consecutive curls, run 27INR0536.
Real example: 27INR0536 (deep, terminal state max_turns)
Bash:curl:interchange.puc.texas.gov > Bash:curl:interchange.puc.texas.gov > Bash:curl:interchange.puc.texas.gov > Bash:curl:interchange.puc.texas.gov > Bash:curl:interchange.puc.texas.gov > Bash:curl:interchange.puc.texas.gov > Bash:curl:interchange.puc.texas.gov > Bash:curl:interchange.puc.texas.gov > Bash:curl:interchange.puc.texas.gov > Bash:curl:interchange.puc.texas.gov
v2 fix: puct.py match / spv.py resolve replace raw WebFetch/curl with the local docket index + on-disk IA PDFs; a domain blocklist blocks direct agent fetches to interchange.puc.texas.gov and efts.sec.gov outright (PLAYBOOK Stage 2 systematic ladder).

Budget-kill work loss

ADDRESSED
33 token-budget kills (30 deep / 3 triage), 23 of them wrote no findings.json/dossier.md at all. Median wall-clock to death: 12.4 min vs 5.2 min for a successful run.
Real example: 25INR0591 (deep, terminal state budget_kill)
Write:log.md > Bash:cat > Edit:log.md > Bash:curl:zeusred.com > Bash:gmaps.py:places > Bash:gmaps.py:places > Agent:Agent > ToolSearch:ToolSearch > WebFetch:interchange.puc.texas.gov/searc > WebFetch:interchange.puc.texas.gov/searc
v2 fix: Checkpointed deep stages: D0 writes the full findings.json skeleton BEFORE any research begins, and each stage (D1–D5) ends with a checkpoint write — a budget-kill now loses at most one stage's work, never all of it.

Max-turns exhaustion

ADDRESSED
28 runs (22 deep / 6 triage) hit the SDK turn cap. Last 10 tool calls of these runs: 18 stage0_queue, 66 other, 37 wrapup, 52 imagery, 107 web_research — still researching or re-running wrap-up scripts, not finishing.
Real example: 25INR0052 (deep, terminal state max_turns)
Bash:cat > Write:dossier.md > Write:findings.json > Bash:queue_history.py > Bash:build_brief.py > Bash:python3 > Bash:build_brief.py > Edit:findings.json > Bash:build_brief.py > Bash:build_brief.py
v2 fix: Deterministic wrap-up (D5: queue_history.py → eia_history.py → build_brief.py → build_index.py) runs ONCE instead of an agent-driven rebuild loop; a checkpoint watchdog (PostToolUse) counts tool calls since the last findings.json write and injects a warning turn past 25, forcing a checkpoint before the turn cap is reached.

Search-engine HTML scraping

ADDRESSED
7,260 WebFetch calls to html.duckduckgo.com / www.bing.com / search.yahoo.com search-result pages (28.0% of all WebFetch, 12.5% of all 57,865 tool calls) — done in place of a search tool.
Real example: 22INR0203 (triage, terminal state hung_hardkilled)
WebFetch:comptroller.texas.gov/economy/d > WebFetch:comptroller.texas.gov/economy/d > Edit:log.md > WebFetch:www.bing.com/search > WebFetch:www.bing.com/search > WebFetch:www.bing.com/search > WebFetch:www.bing.com/search > Edit:log.md > Write:triage_findings.json > Write:triage.md
v2 fix: search.py "<query>" is the one search entrypoint (AgentCore Gateway → OAuth bridge → DDG HTML ladder, 7-day cache, banned queue-tracker domains suppressed at the tool layer) — agents are blocked from scraping search engines directly.
